北京两站的官方脚本采用 `Pager({size, current, prefix:'index', suffix:'html'})`，从 `index_1.html` 开始表示第二页。适配器检查参数、请求页码与页面声明页码一致；结构变更、重复返回首页或不合法页码会报错。运行上限设为 60 页，未来达到上限而仍有下一页时保留 `partial`；当前检查中没有碰到这个上限。分页遍历结束只表示本次官网可见目录结束，不证明过去删除、撤下、迁移的公告仍然齐全。

福建科技厅原有目录此次首页包含 72 条目录链接，现有同域 HTTPS 规则接受 68 条。另外四条为科技厅指向福建人社厅的 HTTP 外链，未跟进详情、未把 HTTP 改写后当作已验证原文。这些链接帮助确认了上表人社厅招聘公示栏目，但两来源仍分别保留来源归属。

科技厅页面声明“动静结合”、`maxStaticIndex: 7`、每页 15 条；页面显示的分页与 HTTP 文件页不是一回事，不能凭常见 `index_N` 模式猜测历史分页。用于核验其动态目录实现的官方公共脚本主机本次在 robots 请求阶段超时，因此科技厅历史能力维持未接入，后续仍需验证公开目录服务后才能改变状态。

## 失败和测试记录

- 北京首都之窗首次首页抽查成功，随后第一次整栏核验在 robots 请求阶段超时；之后一次复核通过全部 7 页。失败保留在本机 `data/extra-source-verification.jsonl`，未通过关闭 TLS、换身份或绕过访问控制重试。
- 北京经信局整栏核验通过全部 8 页，各页招录元数据数为 20、19、20、20、19、19、19、14。
- 新增 `tests/test_extra_sources.py`，7 项脱敏测试通过：来源范围、零基分页和跨年公告、结构漂移和首页重复、外域/错误目录/附件排除、未知日期不取 URL 日期替代、无关人事条目过滤、福建静态目录保留历史缺口。
- 招考年度使用主模块的 `exam_year_from_title`。公告发布日期来自目录显示的日期；两者分开，标题年度有歧义时保持未知，不能依靠发布时间补出考试年度。
- 研究核验结果和历史位于 Git 排除的 `data/`，不上传目录 HTML、公告详情或人员名单。应用集成及完整回归验证由主任务另行记录。
