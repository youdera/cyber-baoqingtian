# 0.2 公告浏览与更新提醒

入口notice_app.py；start.cmd、start.ps1及公开版app.py均进入当前应用。旧数据不迁入公告索引。

## 查询与时间

- 公示发布时间与招考年度独立，至少设置一种；单边按单月或单年补齐，同时设置取交集，月份包含首尾日。
- 默认省内招录；全国／中央招录单独选择。地区按发布来源归属，岗位所在地以原文为准。
- 查询只读已采集索引；手动检查和定时闹钟才访问官方目录。更多条件包含公告阶段和发布栏目。
- 年度只从标题保守识别；歧义与缺失保留未知。旧缓存查询时重算年度；不改写历史记录。
- 只保存公告元数据与原文链接，不下载、索引人员名单或关联身份。

## 提醒

本机可设北京时间每日固定时间或6/12/24小时。程序需保持运行；关闭期间不检查，重启合并补查。未读优先每批200条，标已读后显示下一批；同一公告恢复旧内容也作为新的元数据变更提醒。浏览器系统通知需主动授权和页面保持打开，其实际系统投递仍未验证。

GitHub云端条件由cloud-watch.json单独配置，支持同样的三种时间组合；本机保存不会自动同步。每天09:17检查已接入栏目，每周日09:37来源巡检。定时可能延迟，邮件或手机通知取决于GitHub设置。扩展后云端使用90分钟采集预算、120分钟工作流，超时完成收尾后报告未检查来源，确认后轮转下次起点；来源内部仍从首页检查。

## 来源

当前72个已接入栏目，登记130个入口；31个省级地区及兵团均至少有一个局部栏目，全国／中央2个栏目单列。新增54栏目统一抽查94页、2213条来源记录（最多前2页），不等于各栏目历史已全部采集。详见SOURCE_EXPANSION_20260913.md及SOURCE_COVERAGE.md。

来源页新增地区过滤和地域缺口汇总；具体失败区分robots/目录请求阶段、TLS、HTTP状态和超时。仅BAD_ECPOINT使用标准P-256曲线重试，证书和主机名验证继续开启。深圳、湖南本机实测恢复，其他TLS问题或403、校验响应仍保留失败。

各栏目固定分页窗口、总数不符、站外引用及直接附件排除保持partial，上海末页404与福建动态历史等缺口仍存在。至少一个局部来源不能代表全省或所有发布单位。

同URL在多个栏目出现时保留各来源快照，按来源独立判断元数据变化；查询合并同一公告，明确匹配优先于待核对，并展示匹配来源。跨页置顶条目计数去重、整页重复返回报错。公开目录API与可打开的官方栏目入口分别配置，读取仍限同域HTTPS。

GitHub首次引入新来源时建立独立基线，不将已有历史逐条提醒；读到目录并确认报告后才保存该来源基线，首次失败后恢复仍先初始化。

固定官方HTTPS来源、robots、TLS、DNS校验、限速和失败记录保持启用；不绕过访问限制。北京分页回跳、模板变化等会报错，不能当作零公告或完整结束。

## 限制与验收

尚无全国发布主体完整目录、全部历史分页、ETag和断点续采、附件内容更新检测、网站与GitHub自动同步或公网多用户服务。登记和页数不是全国覆盖率。

本轮自动测试包括时间边界、跨年、旧缓存、闹钟、未读分批、元数据恢复、启动入口、来源分页和云端报告。浏览器验证独立时间与交集、关注回填、新省份栏目和实际采集。最终测试数量与云端状态见HANDOFF最新日志。
