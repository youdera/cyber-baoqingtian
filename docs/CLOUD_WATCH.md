# 公示查询与定时提醒

本项目提供官方公告链接检索与新公示提醒，仅处理公告元数据，不下载或索引人员名单，不关联身份或自动举报。

## 本地使用

运行 `python notice_app.py --open`，按发布起止年月、招考年度、类型、地区及发布栏目查询。默认只看录聘公示及更正、撤销。查询后保存关注，可设置每天北京时间的检查时间，或6/12/24小时间隔，并开启站内提醒。浏览器通知需用户主动授权且页面保持打开。关闭电脑后本机不检查；重启后合并补查到期任务。

## GitHub云端检查

`.github/workflows/notice-watch.yml` 每天北京时间09:17运行，可从Actions手动触发。定时可能延迟。`cloud-watch.json`是云端关注范围，初始为2026年公告、不限招考年度、全部已接入栏目、仅录聘公示及更正撤销。网站保存的关注条件不会自动同步到GitHub。

第一次运行、缓存丢失或查询条件变化时建立基线并通知来源状态，不逐条推送历史记录。之后仅在发现未读公告变化或来源状态改变时创建Issue并指派仓库所有者。是否收到邮件/手机推送由GitHub通知设置决定；本项目不直接发送邮件。失败的工作流还需查看Actions状态。云端网络与本机不同，必须查看实际运行报告，不能以本机成功代替云端验收。

每个来源另有独立的首次基线。更新项目、增加新栏目时，只抑制该栏目首次读取的历史公告提醒，已初始化来源的正常更新照常提醒。来源首次失败、没有读到任何目录页时，不算完成初始化；下次恢复可读取时仍先建立基线。这里的“初始化”仅表示至少读到一页目录，不代表该来源或历史已经完整覆盖；`partial`仍保留原来的缺口原因。

已初始化来源ID保存在云缓存的 `baseline.json` 的 `sources` 字段。本轮结果先写 `artifacts/pending.json`，由报告确认步骤 `--ack` 执行后生效；没有确认时，下轮继续首次检查。升级前的标记没有 `sources` 时，只从旧 `health` 中成功或部分完成的来源迁移已知状态，失败、未知或不可解析的状态仍视为尚未初始化。修改查询条件会为当前选中范围重新建基线。

元数据状态通过Actions缓存保存，缓存不是永久档案；报告作为artifact保留30天。新发现可能是历史补采，元数据变化不包含同URL附件内部变化。页面信息缺失时标为待核对。来源不可用不等于没有公告。

## 来源覆盖

实际接入清单以网页“已接入栏目”和代码中的固定来源配置为准。各来源的历史范围和失败原因分别展示；福建的部分历史分页尚未接入，广东省厅栏目达到200页上限时仍保留partial。地区选项不表示各省已接入，不宣称全国完整覆盖。新增适配的实测记录见对应来源说明和发布说明。

## 来源目录自动巡检

source-audit.yml每周日北京时间09:37批量巡检固定登记入口，或手动触发；与公告定时共享运行互斥组。具体入口数随已核验来源配置更新，以本次报告为准。最多3个不同域名并发，同一域名串行限速。只读取入口目录，门户中发现的候选栏目只作为链接报告，不自动加入正式公告索引。报告保留30天。

本机可在来源页启动和停止巡检，结果保存为data/source-audit.json，历史追加至data/source-audit-history.jsonl。也可运行python scripts/audit_sources.py，默认保存到data/source-audit/。


时间条件至少一种；只填year_from即可按该招考年度检查，不限制公示日期。也可只填month_from查单月，或设置两种范围取交集。缺失或歧义年度单列待核对。配置示例及云端核验见[CLOUD_CHECK_UPDATE.md](CLOUD_CHECK_UPDATE.md)。
