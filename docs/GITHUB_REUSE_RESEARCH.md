# GitHub 公示采集项目研究汇总

核验日期：2026-09-12。目标是寻找能帮助扩展官方招录公告目录的现有实现。本轮检查真实源码、分页行为、维护记录与许可证，未执行第三方爬虫，也未把仓库附带的数据导入项目。

## 结论

有可用的接口和栏目线索，最值得继续研究的是 RSSHub 的考试栏目路由、china-governance 的广东政府目录模板。本轮没有验证到一个能直接补齐剩余入口、并保证全国历年拟录聘公示完整的现成系统。

研究时项目为 **64 个登记入口、6 个正式采集栏目、58 个待接入入口**。后续实际接入与最新数量见 [来源接入验收](SOURCE_INTEGRATION_20260912.md)。登记入口、适配器文件、第三方列出的省份，都不能当作已完成覆盖的证据。

## 候选项目比较

| 项目 | 代码中实际存在的能力 | 对本项目的用途与限制 |
| --- | --- | --- |
| [DIYgod/RSSHub](https://github.com/DIYgod/RSSHub) | 浙江公务员、山西人社、四川人事考试、重庆人事考试等栏目路由 | 最直接的招录栏目线索。多为最新一页或有限条数，官网当前可用性和历史分页仍需核验；当前核验版本为 AGPL-3.0 |
| [hulelan/china-governance](https://github.com/hulelan/china-governance) | 广东 gkmlpt 栏目发现、分页 JSON；部分 XML 目录解析 | 有望减少多个同模板网站重复适配的工作。未找到许可证，且默认流程抓正文、关闭 TLS 验证；仅研究公开接口后独立实现 |
| [SuperJJ2333/Crawler_of_China_govern_website](https://github.com/SuperJJ2333/Crawler_of_China_govern_website) | 多省市政府站采集脚本、站内搜索接口示例 | 可补接口线索；样例主要采集政府新闻，入口有占位配置，不能直接替代招录目录。实际 LICENSE 为 Apache-2.0，与 README 的 MIT 描述不一致 |
| [SmartDataLab/Policy_crawler](https://github.com/SmartDataLab/Policy_crawler) | 多省政策目录 Scrapy 爬虫 | 可参考模块组织，MIT；代码较旧，固定页数、政策正文采集不能满足当前招录检索 |
| [dgtlmoon/changedetection.io](https://github.com/dgtlmoon/changedetection.io) | 页面变化检查、选择器、定时与通知 | 适合提醒功能参考，不能自动补齐官方来源目录 |
| [scrapy/scrapy](https://github.com/scrapy/scrapy) | 抓取调度、限速、重试、断点续跑 | 来源扩大后可评估；采用框架仍需逐站适配，暂不为换框架重写现有应用 |

一些名称接近“全国招聘监控”的仓库，实际使用第三方聚合站、只支持少数栏目，或在失败时返回示例公告。不能只看 README 省份清单就纳入生产采集，详见招录项目专项核验。

## 建议实施顺序

1. 根据 RSSHub 的已读路由，优先复核四川、重庆的 HTTPS 目录，再处理山西和浙江栏目。浙江需要单独解决 POST 详情入口与可分享原文链接的问题。
2. 根据广东官网公开目录独立实现 gkmlpt 元数据适配器。复用的是目录格式解析机制；每个站点的招录栏目、归属和允许访问域名仍需固定配置并验收。
3. 每项接入验证标题、发布日期、链接、后续页和终点依据；未知年份、日期缺失、重复页、访问失败和历史窗口均保留具体状态。采集失败不能推断公告撤销。
4. 增量检查与历史回补分别调度，继续使用现有 GitHub 定时与公告版本去重。现成 RSS 最新条目不等于全年归档，省级栏目也不等于全省所有单位。

当前证据更支持“按政府目录模板扩展、逐栏目核验”，无需用 AI 猜测页面数据，也无需整体替换现有查询和提醒系统。
