## 校验中修复的问题

- 甘肃早期公告使用 `article_N` 加 12 位数字，近年使用 32 位十六进制 ID。初次末页因只认近年格式而报解析失败；随后核对同一官方末页、加入旧格式和脱敏回归，末页 11 条验证通过。没有用“零条”掩盖该失败。
- 陕西目录标题和发布日期位于同一个链接内部，分别提取 `.text` 和 `.time`，不把发布日期拼进标题或误认成招考年度。
- 云南事业单位页面顶部有其他栏目的滚动新闻。仅读取招聘列表，并要求详情链接的 ClassID 也是 602；不用全页面链接扫描冒充目录。
- 新疆公务员、事业单位两个栏目会转载其他考试类型，均设为混合来源。在新疆地区范围内，按省考、国考或事业单位筛选采集、设置关注时都可选中这两个栏目。来源原有类型保存在 `default_kind`；公告标题明确包含事业单位、公务员或中央机关公务员考试时使用对应类型，否则保留来源默认类型。这与地区范围独立，不会把新疆栏目改为“中央/全国”来源。
- 新疆公务员栏目有指向本站其他栏目下原文的链接，保留本站固定公告路径，避免漏掉同站跨栏目转载。
- 已识别为同站公告链接的条目，提取后的标题为空、仅含空白或超过 500 字符时明确报解析失败；即使同页还有正常条目，也不会静默跳过异常标题并报告成功。
- 日期缺失或无效保持未知，不拿 URL 日期或考试年份补齐。缺少分页标记、页码与请求不一致、无法识别目录等均报错；有效混合目录过滤为零条时可以继续后续页。
- 本轮只索引同站 HTTPS HTML 公告。跨站转载和直接 PDF/XLSX 入口作为明确缺口记录；不自动访问那些目标来补正文。

修复后 **34 个不同目录页样本均可解析**，其中甘肃的 3 个样本复核了一次。每个有后续页的栏目均检查首、次页 ID 集合不同。`tests/test_expansion_west.py` 的 **12 项脱敏测试通过**，涵盖全部 13 种来源配置、首/次/末页、重复首页、错误主机和类别、模板变化、日期未知、混合栏目、旧公告格式及兵团静态上限。此验证不替代主任务的实际入库和浏览器验收。

## 交付与主模块接线

逐地区机器可读盘点位于 **`data/expansion-west-inventory.json`**，共 11 个地区，含具体栏目、状态、失败层级、时间、来源 ID 与剩余缺口。它和 `data/expansion-west-validation*.json` 仅留本机，不提交 Git。公开材料为本说明、适配器和脱敏测试。

主任务需把 13 个固定配置加入来源注册，`listing()` 分派到 `parse_expansion_west`，并让 source audit 使用相同解析器。省级范围映射可用 `{s['id']: s['area_scope'] for s in EXPANSION_WEST_SOURCES}`。来源目录测试仅对已证实的 `www.nxpta.com` 增加固定例外；保留所有 `history=False/history_note`。新增来源的云端首轮基线按主模块已有逻辑处理。

本次没有修改 `notices.py`、共享注册或数据库；主任务统一追加 HANDOFF、集成验收和发布。上述结果不构成全国、全省或全年度完整覆盖证明。
